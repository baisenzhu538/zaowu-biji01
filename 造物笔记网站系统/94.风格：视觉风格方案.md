# 造物笔记网站 · 视觉风格方案

> 编制依据：`00.顶层` / `02.创意` / `11.清单` / `22.架构` / `22.设计` / `90.需求` / `92.技术` / `93.交互`
> 编制日期：2026-09-26
>
> 本文提出 **5 套视觉风格方案**，每套说明三件事：**优点 / 风险 / 适合的页面**。
> 目的是给老板一个可挑的清单，**不是终稿**——选定后再展开成设计规范。

---

## 一、先看清我们要服务什么

风格不能凭空提，先锁定三组事实约束。

### 1.1 用户是谁

| 事实 | 出处 | 对风格的约束 |
|---|---|---|
| 一堂同学，**VibeCoding 新人小白** | 00.顶层 | 不能有"高级感压迫"——太酷炫会让人不敢用 |
| **被名词卡住 → 恐慌焦虑** | 00.顶层 | 第一眼要"稳、可信、有秩序"，降低焦虑是第一诉求 |
| 三类人共用：零基础 / 有基础 / 看方法论 | 11.清单 | 同一页面要容得下"必知必会"和"专业理解"两种深浅 |

### 1.2 内容是什么

| 内容 | 形态 | 规模 |
|---|---|---|
| Top 50 名词 | 每词 4 字段 + 3 条话术，**结构高度一致** | 50+ 页 |
| 3 个武器库 | 长文、含表格/梯度图/话术卡，**一页到底不折叠** | 3 页 × 700+ 行 |
| 陪练对话 | 对话流 `[缺口]` 未设计 | 待定 |

**关键事实**：内容本身已经很"重"——50 词 × 9 类、700 行 wiki、方法论密集。**风格必须做减法，不能抢内容的戏。**

### 1.3 已经定死的设计参数（不能违背）

| 项 | 值 | 出处 |
|---|---|---|
| 侧边栏宽度 | 桌面 200px，移动折叠 | 22.架构 |
| 内容区最大宽度 | **680px，居中偏左** | 22.架构 |
| 章节标题字体 | **Manrope Variable**，wght 650-720，字号 22-28px | 22.架构 |
| 策略梯度 | **🟢🟡🟠🔴 四色标签** | 22.架构 |
| 话术区 | **浅蓝背景卡片 + 复制按钮** | 22.架构 |
| 名词三色标 | 必知必会🟠 / 口语化🟢 / 专业🔵 | 02.创意 |
| 技术栈约束 | **原生 CSS + CSS 变量，不引 UI 组件库** | 92.技术 |

> ⚠️ **重要约束**：`92.技术` 已定"原生 CSS + CSS 变量"，意味着**每套风格都必须靠 CSS 变量落地**，不能靠组件库开箱样式。这反而是好事——五套风格其实可以共用同一套变量骨架，只换色板/圆角/投影/密度四组值。

## 二、五套方案速览对比

| # | 方案 | 一句话感觉 | 信息密度 | 开发成本 | 最大风险 |
|---|---|---|---|---|---|
| A | **极简文献风** | 像一本排版讲究的书 | 高 | 低 | 容易"性冷淡"，缺亲和力 |
| B | **工业手册风** | 像一本技术手册/说明书 | 很高 | 低 | 视觉偏硬，小白可能觉得"冷" |
| C | **卡片工具站风** | 像一个好用的小工具集合 | 中 | 中 | 卡片泛滥会稀释 680px 阅读区 |
| D | **杂志编辑风** | 像一期讲设计的杂志 | 中低 | 高 | 排版成本高，与"一页到底"有张力 |
| E | **终端极客风** | 像开发者的编辑器 | 高 | 中 | 与"小白降低焦虑"的初衷**直接冲突** |

**我的倾向**：**A 为主 + C 的局部借用**（名词页用卡片、Wiki 页用纯文献排版）。理由写在第五节。

## 三、逐套详解

## 方案 A · 极简文献风（Editorial Minimal）

> **一句话**：去掉一切装饰，让内容本身成为界面。

### A.1 视觉特征

- **色调**：近白背景（`#FAFAF9` 暖白，非纯白）、深墨字（`#1A1A1A`）、**唯一强调色是橙色**（承接"必知必会🟠"）
- **字体**：Manrope Variable 独占，靠 **字重落差**（650 正文标题 / 420 正文）建立层级，不靠颜色
- **圆角**：极小（4px），甚至直角
- **投影**：几乎不用，靠 **1px 淡边框 + 留白** 分隔
- **装饰**：零。没有渐变、没有插画、没有 emoji 装饰
 
### A.2 优点

| 优点 | 说明 |
|---|---|
| **内容密度天然友好** | 680px 内容区 + 无装饰 = 700 行 wiki 读起来不累，这正是架构要的"信息密度高" |
| **开发成本最低** | 只有色板 + 字重 + 间距三组变量，**CSS 变量骨架 1 天能搭完** |
| **永不过时** | 不追视觉潮流，两年后看依然不土 |
| **三种深浅内容统一** | "必知必会"和"专业理解"在同一视觉语言下，只靠字重和缩进区分，不割裂 |
| **降低焦虑** | 没有花哨元素，视觉噪音为零，新人不会"不知道点哪" |
| **移动端近乎零成本** | 单列流式排版天生响应式 |

### A.3 风险

| 风险 | 严重度 | 说明 |
|---|---|---|
| **"太素"，缺记忆点** | 高 | 交付物同时是**一堂的官方示例案例**（00.顶层价值1），太朴素不足以"演示方法论" |
| **对新人不够友好** | 中 | 纯文献感缺少"游戏化/引导感"，可能与"保 5 争 10 的创意惊喜"（02.创意）相悖 |
| **首页难出彩** | 中 | 四维装备卡如果也用极简风，四张卡会像四行字，失去"装备"感 |
| **全站靠排版功力** | 中 | 极简风"一眼看出好坏"，行高、字距、留白有任何一处没调好就露怯 |

### A.4 适合的页面

| 页面 | 适配度 | 说明 |
|---|---|---|
| **Wiki 长页（3 个）** | ⭐⭐⭐⭐⭐ | **最佳主场**。700 行连续滚动 + 侧边栏 TOC，极简风让它像一本排版讲究的电子书 |
| 名词内容页（50+） | ⭐⭐⭐⭐ | 结构一致的四字段天然适合文献式排版 |
| 搜索筛选页 | ⭐⭐⭐ | 可用但需补一些轻交互反馈 |
| 首页 | ⭐⭐ | **弱项**。需要额外借卡片元素，否则太平 |
| 陪练页 | ⭐⭐ | 对话界面极简风会显得"冷"，缺少陪伴感 |

## 方案 B · 工业手册风（Technical Manual）

> **一句话**：像一本严谨的设备说明书，处处有编号、有索引、有警示框。

### B.1 视觉特征

- **结构感极强**：章节编号外显（`01 / 02 / 03`）、左侧竖线标识层级、大量分隔线
- **色板**：冷灰底（`#F5F6F7`）+ 深蓝黑字 + **功能色系统化**
  - 警示黄（`#F5A623`）、风险红（`#D0021B`）、安全绿（`#417505`）
- **字体**：标题 Manrope 700+，**正文引入等宽字体**（用于名词英文名、代码、路径）
- **框型组件**：`提示框 / 注意框 / 警告框` 三色边框
- **隐喻**：每一页像手册的一章，可被"索引"和"翻阅"

### B.2 优点

| 优点 | 说明 |
|---|---|
| **极度契合"武器库"定位** | "实战锦囊"本质就是手册，工业风的"查阅感"直接命中 |
| **天然支持梯度分级** | 🟢🟡🟠🔴 四色可直接长成"难度/风险等级"的视觉语言 |
| **等宽字体解决一个真问题** | 名词页有 `Frontend & Backend`、`localhost`、`npm` 等英文与代码，等宽字体区分度更好 |
| **降低焦虑** | 手册感 = "有章法"，新人面对有编号有索引的东西比面对空白页面安心 |
| **三种深浅内容好分层** | "专业理解"可用灰底框收纳，与"大白话"视觉上明确区分 |
| **复用 22.设计的方法论** | 文档本身有"四层诊断法""三色标签"，工业风是把这些视觉系统化 |

### B.3 风险

| 风险 | 严重度 | 说明 |
|---|---|---|
| **视觉偏硬、偏冷** | 高 | 服务对象是"恐慌焦虑的新人"，工业风可能加重"这东西很专业我搞不懂"的心理负担 |
| **和"口语化🟢"的调性打架** | 中 | 项目很大一部分魅力在"口喷话术"的生活化语气，冷硬手册风与口语化内容有气质冲突 |
| **组件数量多** | 中 | 提示框/注意框/警告框/编号系统/索引，**CSS 变量要管理的项比 A 多 2-3 倍** |
| **容易做成"文档站"** | 中 | 与 92.技术 里已提示的风险叠加：VitePress 自带文档感，工业风会**双重强化**文档感，失去产品站气质 |
| **首页装备卡不好做** | 中 | "四维能力装备卡"需要一点游戏化想象，工业风里很难做出"装备"的感觉 |

### B.4 适合的页面

| 页面 | 适配度 | 说明 |
|---|---|---|
| **Wiki 长页（3 个）** | ⭐⭐⭐⭐⭐ | 与左侧 TOC + 长文结构完美契合 |
| **名词内容页（50+）** | ⭐⭐⭐⭐⭐ | **等宽字体 + 四字段结构**是本方案最大优势 |
| 搜索筛选页 | ⭐⭐⭐⭐ | 九大分类卡片做成"索引卡"很自然 |
| 首页 | ⭐⭐ | 装备卡会做得很生硬 |
| 陪练页 | ⭐ | **最弱**。对话界面套手册风会毫无陪伴感 |

## 方案 C · 卡片工具站风（Toolbox / Card-based）

> **一句话**：像一个收纳整齐的工具箱，每件工具一张卡，点开就用。

### C.1 视觉特征

- **卡片是基本单位**：圆角 12-16px、柔和投影（`0 2px 8px rgba(0,0,0,.06)`）、hover 上浮 2px
- **色板**：明亮、有活力。主色蓝 + 四维装备卡各配一个主题色
- **图标为主**：每张卡配内联 SVG 图标（92.技术 已定"内联 SVG 不用图标库"）
- **网格布局**：分类页用 2-3 列网格
- **交互反馈丰富**：hover 放大、点击涟漪、卡片翻转

### C.2 优点

| 优点 | 说明 |
|---|---|
| **对新人最友好** | 卡片 = 明确的"可点击"信号，新人不会迷路 |
| **首页能出彩** | "四维能力装备卡"在卡片风里才能真正做成"装备"的样子，直接兑现 02.创意的惊喜设计 |
| **九大分类天然适配** | 50 词分 9 类，卡片网格是最自然的呈现 |
| **话术卡片顺理成章** | 架构已定"话术区 = 浅蓝背景卡片"，卡片风让全站语言统一 |
| **信息分块降低焦虑** | 每张卡只承载一件事，符合"3 秒查到"的目标 |
| **可渐进增强** | 先做静态卡片，后续加 hover/动画都容易 |

### C.3 风险

| 风险 | 严重度 | 说明 |
|---|---|---|
| **与 680px 阅读区冲突** | **高** | 架构定死内容区 680px，但卡片网格需要更宽。两套布局要共存，**边界处理不好会显得割裂** |
| **卡片泛滥稀释重点** | 高 | 全站卡片 = 没有重点。四维装备卡、九大分类卡、50 个名词卡、话术卡……全是卡，视觉会平 |
| **长文页面会出现"卡片尴尬"** | 中 | 700 行 wiki 一页到底，卡片风在长文里没有用武之地，只能退回文献排版 → **风格不统一** |
| **投影/圆角/动画会拉长开发时间** | 中 | 比方案 A 多 2-3 倍样式工作 |
| **容易做成"模板站"** | 中 | 卡片 + 投影 + hover 上浮是 bootstrap 时代的通用脸，缺辨识度 |

### C.4 适合的页面

| 页面 | 适配度 | 说明 |
|---|---|---|
| **首页** | ⭐⭐⭐⭐⭐ | **最佳主场**。四维装备卡在卡片风里最有说服力 |
| **搜索筛选页 / 九大分类** | ⭐⭐⭐⭐⭐ | 网格卡片是分类浏览的最优解 |
| 名词内容页 | ⭐⭐⭐⭐ | 话术卡 + 相关推荐卡很自然，但正文要克制别过度卡片化 |
| 陪练页 | ⭐⭐⭐ | Agent 选择卡合适，对话气泡区不需要卡片风 |
| Wiki 长页 | ⭐⭐ | **弱项**。长文里卡片是干扰 |

## 方案 D · 杂志编辑风（Magazine Editorial）

> **一句话**：像一期讲 AI 编程的设计杂志，大标题、大留白、大图片。

### D.1 视觉特征

- **排版即设计**：超大标题（40-56px）、大量留白、正文两栏（宽屏）
- **字体组合**：Manrope 做标题 + **衬线中文字体**做正文（如思源宋体）——靠衬线/无衬线对比制造"杂志感"
- **大色块**：每章一个主题色块打底
- **图片/插画**：需要视觉素材（这是最大成本）
- **网格系统**：严格的栅格

### D.2 优点

| 优点 | 说明 |
|---|---|
| **调性最贴"审美赋能"** | 项目定位是"UX 审美是第二护身符"（22.设计），**网站自己就是审美示范**——杂志风最有说服力 |
| **记忆点最强** | 五套里辨识度最高，最容易成为"官方示例案例"的门面 |
| **大标题利于"3 秒查到"** | 名词页大字标题 + 一句话解读，扫读效率高 |
| **衬线中文解决阅读疲劳** | 700 行长文用衬线，比无衬线耐读 |
| **讲述感强** | 项目有大量"故事"（六个尴尬瞬间、残酷事实），杂志风讲得好 |

### D.3 风险

| 风险 | 严重度 | 说明 |
|---|---|---|
| **开发成本最高** | **高** | 需要栅格系统 + 字体组合 + 响应式排版规则，**是方案 A 的 3-4 倍工作量** |
| **与"一页到底不折叠"有张力** | **高** | 杂志靠"翻页节奏"制造体验，但架构明确要求"不做折叠、连续滚动"，核心手法被限制 |
| **需要视觉素材** | 高 | 杂志风没图会垮，但项目现有资产只有 50 个名词 + 3 篇长文，**没有配图** |
| **衬线中文的 web 加载** | 中 | 衬线中文字体体积大，与 92.技术"尽量轻"的原则冲突 |
| **与 92.技术的 VitePress 冲突** | 中 | VitePress 的默认排版系统面向文档，改成杂志排版要大量覆盖，**等于和框架对抗** |

### D.4 适合的页面

| 页面 | 适配度 | 说明 |
|---|---|---|
| **首页** | ⭐⭐⭐⭐⭐ | Hero 大标题 + 大留白，最能立住品牌 |
| Wiki 长页 | ⭐⭐⭐ | 开篇章节适合杂志式展开，中段 10 条策略会重复 |
| 名词内容页 | ⭐⭐⭐ | 大字标题好，但 50 个页面套杂志排版会显得"用力过猛" |
| 搜索筛选页 | ⭐⭐ | 网格浏览与杂志的单列叙事不搭 |
| 陪练页 | ⭐ | 对话界面套杂志风非常别扭 |

## 方案 E · 终端极客风（Terminal / Dev Tool）

> **一句话**：像一个精心设计的开发者工具，等宽字体、深色、命令行感。

### E.1 视觉特征

- **深色为主**（`#0D1117` 系列），或"亮色底 + 终端窗口"混搭
- **等宽字体为主角**（JetBrains Mono / Fira Code）
- **命令行元素**：`$` 提示符、光标闪烁、打字机动画
- **语法高亮色板**：用 IDE 的配色逻辑做界面
- **对话感**：陪练页做成"终端对话"

### E.2 优点

| 优点 | 说明 |
|---|---|
| **技术可信度最高** | 一个讲 VibeCoding 的站用极客风，气质上是自洽的 |
| **陪练页最贴** | 两个 Agent 是"技术名词解读 Partner / 技术配置专家"（00.顶层），终端风格天然匹配 |
| **等宽字体解决代码展示** | 名词页、调试篇、版本管理篇都有大量命令行内容 |
| **差异化强** | 同类"名词解释站"基本都是亮色文档风，深色终端风容易出圈 |
| **深色护眼** | 长文阅读在深色下对部分人更舒适 |

### E.3 风险

| 风险 | 严重度 | 说明 |
|---|---|---|
| **与核心诉求直接冲突** | **极高** | 项目要解决的是"新人恐慌焦虑"（00.顶层），**终端风是最容易让小白劝退的风格**。这是根本性矛盾 |
| **与已定参数冲突** | 高 | 架构定"话术区浅蓝背景卡片""🟢🟡🟠🔴 四色标签"，这些在深色底上都要重调对比度 |
| **700 行长文深色阅读** | 高 | 深色底长篇中文阅读比亮色累，wiki 是"通读"场景 |
| **打印/投屏不友好** | 中 | 项目定位含"现场使用工具"，现场投屏深色底效果差 |
| **🎨 做好看 Wiki 自我矛盾** | 中 | "做好看"这篇在讲怎么做出好看的界面，结果网站本身是终端风 |

### E.4 适合的页面

| 页面 | 适配度 | 说明 |
|---|---|---|
| **陪练页** | ⭐⭐⭐⭐⭐ | **唯一真主场**。对话/Agent 交互与终端隐喻完美契合 |
| 不怕错 Wiki | ⭐⭐⭐⭐ | 调试主题天然适合终端感 |

## 五、我的建议

### 5.1 推荐：以 A（极简文献风）为底，在首页和分类页局部借 C（卡片工具站风）

**理由**：

1. **架构已经把答案写了一半**。架构说名词页和 wiki 页是两种模式，那风格上也不该强求统一——**A 负责长文与名词正文，C 负责首页与分类网格**，正好对应架构的两分法。

2. **680px 的内容区是硬约束**。A 是唯一一个天生为 680px 单列阅读设计的方案，C 的网格布局本质上是外挂在内容区之外的（首页、分类页可以不受 680px 限制，宽屏铺开）。

3. **不敢拿"降低焦虑"冒险**。B 太冷、E 直接冲突、D 成本过高。A 的零噪音视觉是最安全的底。

4. **成本可控**。A 的风格变量只有色板 + 字重 + 间距；C 的卡片只需在首页和分类页用，不污染长文页。

5. **符合"设计宪法"思路**。22.设计的第 10 条策略是"制定设计宪法"——**用一套 CSS 变量锁死，全站遵守**，正是 A + C 混合方案最擅长的事。

### 5.2 如果要更出彩：A + D 的首页特化

首页单独用杂志风的 Hero（大标题 + 大留白），内页全部回归 A。**风险**：首页与内页气质断层，用户会觉得"点进去变了个网站"。

### 5.3 不建议：B 或 E 作为全站基调

- **B** 的工业手册感与"口语化话术"的调性冲突，且会叠加 VitePress 自带的文档感。
- **E** 与项目最核心的"降低新人焦虑"直接矛盾，**除非**网站确定要以老手为目标用户——但 00.顶层明确写的是"新人小白"。

但 **E 有一个高价值用法**：**只把陪练页做成终端风**，其余页面不用。陪练页是 Agent 对话场景，终端隐喻合适；且它独立成区，风格不统一也不会伤到阅读体验。

## 六、无论选哪套，都必须解决的 4 个共性问题

这 4 条是五套方案都要面对的，与风格选择无关：

### 6.1 680px 内容区 vs 宽屏首页的矛盾

架构定内容区 680px，但首页四维装备卡、九大分类网格在 680px 里会很挤。
**建议**：区分**阅读容器**（680px，用于名词页/wiki）和**浏览容器**（可 1080-1200px，用于首页/分类页）。这不是违背架构，而是架构里没写明浏览页的宽度。

### 6.2 颜色系统要一次定死

已散落在各文档的色值至少有 7 个：

| 语义 | 色 | 出处 |
|---|---|---|
| 必知必会 | 🟠 橙 | 02.创意 |
| 口语化 | 🟢 绿 | 02.创意 |
| 专业 | 🔵 蓝 | 02.创意 |
| 梯度一级 | 🟢 绿 | 22.架构 |
| 梯度二级 | 🟡 黄 | 22.架构 |
| 梯度三级 | 🟠 橙 | 22.架构 |
| 梯度四级 | 🔴 红 | 22.架构 |

**问题**：🟠 同时是"必知必会"和"梯度三级"，🟢 同时是"口语化"和"梯度一级"——**语义重叠，同一颜色两套含义**，必须裁决。
**建议**：建立**语义色 vs 等级色分离**的两套变量（`--color-semantic-*` 与 `--color-level-*`），即使色值相同也分开定义。

### 6.3 emoji 的去留

架构用 🟢🟡🟠🔴 做梯度标识、首页用 📖🎨🐛💾 做装备卡；
但 92.技术 写"需求要求去掉 emoji 用简洁图标"。
**问题**：**两条指令冲突**，必须裁决。（建议：**保留语义 emoji 作为内容的一部分**，因为彩色的四色圆点和模块 emoji 是 02.创意定的创意点；但界面控件按钮用内联 SVG。）

### 6.4 深色模式要不要做

IDE 主题是 dark，但用户浏览网站的场景未必是深夜。
**建议**：MVP **不做深色模式**，但 CSS 变量按"可切换"的写法组织（颜色全部走变量，不硬编码），后续加暗色只需加一份变量覆盖。
