## 零、页面映射说明

本文档按需求方指定的四类页面组织，与需求清单中的页面类型对应关系如下：

| 本文档页面 | 对应需求清单页面 | 说明 |
|---|---|---|
| **首页** | 首页 | 四维能力装备卡 + 搜索 |
| **笔记详情页** | 名词内容页 + Wiki 长页 | ⚠️ 两种内容形态**交互模式不同**，见第一章说明 |

> 二者必须分别设计，不能混为一谈。

## 一、全局交互约定

### 1.1 全局导航

**用户看到的：** 页面顶部固定导航栏，从左到右：
- Logo（点击回首页）
- 三个模块 tab：**名词解码** / **实战锦囊** / **陪练对话**
- 搜索入口（点击展开搜索框）

**可以点的：**

| 元素 | 点击后 |
|---|---|
| Logo | 回首页 |
| 名词解码 tab | 进入名词浏览入口 |
| 实战锦囊 tab | 进入锦囊目录（三张策略大卡片） |
| 陪练对话 tab | 进入陪练页 |
| 搜索图标 | 展开搜索框并聚焦输入框 |

### 1.2 全局状态处理（所有页面通用）

这是四类页面**都要遵守**的基础约定，后续各章不再重复。

#### 加载中

| 场景 | 表现 |
|---|---|
| 页面级加载 | 顶部进度条（细线，从左到右推进） |
| 内容区加载 | **骨架屏**（Skeleton），占位块尺寸与真实内容一致 |
| 搜索联想 | 输入框下方显示"搜索中…" + 转圈图标 |
| LLM 检索 | 打字机效果逐字输出，同时显示"思考中"提示 |

**原则**：不用全屏转圈遮罩——用户会以为页面卡死。骨架屏让用户预知内容结构。

> 依据：`22.设计` 的"状态问题"诊断原文——"数据加载时页面一片空白（用户以为坏了）"。

#### 空数据

| 场景 | 表现 |
|---|---|
| 搜索无结果 | 空状态插图 + **"没找到「{关键词}」"** + 引导文案 + 推荐 3 个相关名词 |
| 分类下无词条 | "这个分类还在建设中" + 返回上一级按钮 |
| 相关推荐为空 | **整个推荐区块隐藏**（不留空白框） |

**原则**：空状态必须回答"我现在该做什么"，不能只显示空白。
**禁止**：只显示"暂无数据"四个字。

> 依据：`22.设计` 原文——"搜索不到结果时只显示空白页（用户不知道是没数据还是出错了）"。

#### 错误

| 类型 | 表现 | 用户可做的 |
|---|---|---|
| 页面不存在（404） | "这个词还没收录" + 搜索框 + 回首页 | 搜索 / 回首页 |
| 网络错误 | 错误提示条 + **重试按钮** | 点重试 |
| LLM 接口失败 | 保留用户输入 + "AI 暂时没响应" + 重试 | 点重试，输入不丢 |
| 内容加载失败 | 该区块显示占位提示，**其他区块正常显示** | 单独重试该区块 |

**原则**：
1. **错误不吞掉用户输入**——重试时输入框内容还在
2. **局部失败不拖垮整页**——一个推荐模块挂了，正文照常显示
3. **给可执行的动作**——"重试"永远比"出错了"有用

> 依据：`22.设计` 原文——"操作失败 → Toast 提示 + 保留用户输入"、"网络断开 → 顶部提示条 + 离线数据可用标记"。

#### 成功反馈

| 操作 | 反馈 |
|---|---|
| 复制话术 | 按钮短暂变"✓ 已复制"，2 秒后恢复 |
| 切换收藏（如有） | 图标状态即时变化，无需刷新 |

### 2.4 加载 / 空 / 错误

| 状态 | 处理 |
|---|---|
| **加载中** | Hero 区正常显示（静态内容）；装备卡显示骨架块（4 个等宽灰块） |
| **搜索框为空时提交** | 不跳转，输入框轻微抖动 + placeholder 变"请输入要查的词" |
| **卡片目标不存在** | 卡片置灰 + 角标"即将上线"，点击无跳转 |
| **首页整体加载失败** | 显示错误页 + 重试按钮（首页是纯静态，理论上不应失败） |

## 三、笔记详情页

⚠️ **本页有两种形态，必须分别实现。**

### 3.A 形态一：名词详情页（50+ 个）

#### 3.A.1 用户进入后会看到什么

从上到下：

1. **顶部导航栏**
2. **面包屑**：`首页 / 名词解码 / {分类名} / {名词名}`
3. **名词标题区**
   - 色标标签（🟠 必知必会 / 🟢 口语化 / 🔵 专业）
   - 中文名 + 英文名（如"前端与后端 / Frontend & Backend"）
4. **一句话解读**（突出显示，字号较大）
5. **大白话解读**（口语化区块，浅色背景）
6. **专业理解**（**默认折叠**，点击"展开专业解释"才显示）
7. **Vibe 常用话术**（**3 条**，每条一个卡片）

| 话术序号 | 场景 |
|---|---|
| 第 1 条 | 前期设计 |
| 第 2 条 | 中期沟通 |
| 第 3 条 | 后期调试 |

每条话术卡片含：**话术文本 + 复制按钮**

8. **相关推荐**（3-5 个相关名词卡片）
9. **底部**：上一词 / 下一词 导航

#### 3.A.2 可以点什么

| 元素 | 类型 |
|---|---|
| 展开/收起"专业理解" | 折叠切换 |
| 每条话术的复制按钮 | 复制 |
| 相关推荐卡片 | 跳转 |
| 上一词 / 下一词 | 跳转 |
| 面包屑各级 | 跳转 |
| 导航栏 | 跳转 |

#### 3.A.3 点击后会发生什么

| 点击 | 行为 |
|---|---|
| **展开专业理解** | 内容**就地展开**（不跳页、不弹窗），按钮变为"收起" |
| **复制话术** | 话术文本进剪贴板 → 按钮变"✓ 已复制" → 2 秒后恢复 |
| **相关推荐卡片** | 跳转到对应名词详情页（滚动位置重置到顶部） |
| **上一词 / 下一词** | 跳转到**同类目内**的相邻词，滚动到顶部 |
| **面包屑分类名** | 跳到该分类的浏览列表 |

> **"3 秒查到"是核心体验指标**。从点击搜索结果到看清"一句话解读"，
> 中间不应有任何需要展开才能看到的内容——**关键信息必须默认可见**。

#### 3.A.4 加载 / 空 / 错误

| 状态 | 处理 |
|---|---|
| **加载中** | 骨架屏：标题块 + 一句话块 + 3 个话术卡块 |
| **名词不存在** | "这个词还没收录" + 搜索框 + "看看相近的词"（推荐 3 个） |
| **复制的词为空** | 禁用复制按钮（不该出现，属数据质量问题） |
| **话术缺失** | 话术区块显示"话术补充中"，不影响其他区块 |
| **相关推荐为 0** | **整个推荐区块隐藏** |
| **上一词/下一词不存在** | 对应按钮置灰不可点 |

### 3.B 形态二：Wiki 长页（3 个）

#### 3.B.1 用户进入后会看到什么

**桌面端是两栏布局：**

```
┌────────────────────────────────────────────────┐
│  ← 返回首页          顶部导航栏                 │
├──────────┬─────────────────────────────────────┤
│          │                                     │
│ 📑 TOC   │  🎨 做好看 — 打磨出有品质感的界面     │
│ 侧边栏    │                                     │
│          │  ## 开篇：为什么 UX 审美是第二护身符   │
│ ■ 开篇    │  正文…                              │
│ ■ AI味儿  │                                     │
│ ■ 心态篇  │  ## AI 味儿五宗罪                   │
│ ■ 诊断篇  │  正文…                              │
│ ■ 策略    │                                     │
│   1.形容词│  ## 心态篇                          │
│   2.换模型│  正文…                              │
│   …      │                                     │
│ ■ 速查表  │  ← 右下角：回到顶部                  │
│          │                                     │
└──────────┴─────────────────────────────────────┘
```

**关键特征：**
- 侧边栏宽度 **200px**，固定在左
- 内容区最大宽度 **680px**，居中偏左
- **内容不做折叠**，"Wiki 页面就是用来通读的"
- 章节标题用 **Manrope Variable**，字号 **22-28px**
- 策略梯度标识用 **🟢🟡🟠🔴** 四色标签
- 话术区样式与名词详情页**保持一致**（浅蓝背景卡 + 复制按钮）

#### 3.B.2 可以点什么

| 元素 | 类型 |
|---|---|
| TOC 任意章节项 | 滚动跳转 |
| 正文内的话术复制按钮 | 复制 |
| 返回首页 | 跳转 |
| 回到顶部悬浮按钮 | 滚动 |
| 正文内的超链接 | 跳转 |

#### 3.B.3 点击后会发生什么

| 点击 | 行为 |
|---|---|
| **TOC 章节项** | **平滑滚动**到对应章节（不跳页、不改 URL 锚点以外的状态） |
| **滚动页面** | TOC 中当前所在章节**自动高亮**（实现方式：IntersectionObserver） |
| **复制话术** | 同名词详情页：复制 → "✓ 已复制" → 2 秒恢复 |
| **回到顶部** | 平滑滚回页面顶部 |

#### 3.B.4 加载 / 空 / 错误

| 状态 | 处理 |
|---|---|
| **加载中** | 侧边栏 TOC 骨架（几行灰条）+ 正文骨架 |
| **页面内容为空** | "这份小抄还在整理中" + 返回首页 |
| **内容超长导致卡顿** | 图片懒加载；必要时对首屏外内容做延迟渲染 |
| **TOC 为空**（无章节） | 隐藏侧边栏，内容区占满 |
| **内部锚点失效** | 点击无反应时给出提示，不静默失败 |

### 3.C 移动端适配（两种形态通用）

| 桌面端 | 移动端 |
|---|---|
| Wiki 侧边栏 TOC 固定左侧 | **折叠为顶部可展开的下拉** |
| 内容区 680px 居中 | 内容区**全宽** |
| TOC 章节高亮跟随滚动 | TOC 折叠，用户自行展开跳转 |

## 四、搜索筛选页

本页承担**三种模式**，通过 URL 参数区分：
- **搜索模式**：`?q={关键词}`
- **分类筛选模式**：`?category={分类id}`（来自"准确聊"装备卡）
- **目录浏览模式**：无参数（来自"浏览全部"）

### 4.1 用户进入后会看到什么

#### 模式一：搜索模式

1. 顶部导航栏
2. **搜索框**（已填入关键词，可编辑）
3. **结果计数**："找到 12 个相关名词"
4. **结果列表**（卡片流，每张卡片含）：
   - 色标标签
   - 名词名（中文 + 英文）
   - 一句话解读
   - 匹配片段高亮
5. **排序/筛选条**（可选）：按分类筛选

#### 模式二：分类筛选模式

1. 顶部导航栏
2. 页面标题："**准确聊 · 按分类查名词**"
3. **分类卡片网格**
   - ⚠️ **待裁决**：九大分类 or 4 层金字塔（见需求清单）
   - 每张卡片：分类图标 + 分类名 + **词条数**（如"15 个词"）
4. （可选）4 层金字塔模式下显示**章节递进关系**

#### 模式三：目录浏览模式

「名词解码」目录页：卡片式分类浏览
「实战锦囊」目录页：**三张策略大卡片**，直接链接到三个 Wiki 长页

### 4.2 可以点什么

| 元素 | 类型 |
|---|---|
| 搜索框 | 输入 |
| 结果卡片 | 跳转 |
| 分类卡片 | 跳转 |
| 筛选/排序条 | 切换 |
| 清空搜索 | 重置 |

### 4.3 点击后会发生什么

| 点击 | 行为 |
|---|---|
| **输入关键词** | **实时联想**（输入停顿 300ms 后触发），下方显示匹配名词 |
| **回车 / 点搜索** | 进入搜索模式，刷新结果列表 |
| **结果卡片** | 跳转到名词详情页 |
| **分类卡片** | 跳转到该分类的名词列表（仍是本页，切换为筛选模式） |
| **筛选条** | 就地刷新列表（不跳页） |
| **清空按钮** | 清空输入 → 回到浏览模式 |

**搜索匹配范围**：名词名（中/英）、一句话解读、大白话解读、话术文本。

### 4.4 加载 / 空 / 错误

| 状态 | 处理 |
|---|---|
| **搜索中** | 结果区显示"搜索中…" + 转圈；**不清空已有结果** |
| **无结果** | 空状态插图 + **"没找到「{关键词}」"** + 引导文案 + 推荐 3 个热门名词 |
| **搜索框为空提交** | 不提交，提示"请输入关键词" |
| **输入特殊字符** | 正常处理（转义），不报错 |
| **分类无词条** | "这个分类还在建设中" + 返回分类列表 |
| **结果过多（>50）** | 分页或"加载更多"，不一次渲染 |

## 五、陪练页

⚠️ **需求缺口说明**：`00.顶层` 列出了两个 Agent（**教学 Agent：技术名词解读 Partner**、**技术 Agent：技术配置专家 Partner**），但**其余 7 份文档无任何功能设计**。

因此本文档**只定义交互框架骨架**，具体对话能力待设计后补充。

### 5.1 用户进入后会看到什么

1. 顶部导航栏
2. 页面标题："**陪练对话**"
3. **Agent 选择区**：两张卡片

| 卡片 | 名称 | 定位（来自需求） |
|---|---|---|
| 1 | **教学 Agent** | 技术名词解读 Partner |
| 2 | **技术 Agent** | 技术配置专家 Partner |

4. （进入对话后）**对话区**
   - 消息气泡流（用户右侧 / Agent 左侧）
   - 底部输入框 + 发送按钮
   - 顶部显示当前 Agent 名称 + 切换入口

### 5.2 可以点什么

| 元素 | 类型 |
|---|---|
| Agent 卡片 | 选择 |
| 输入框 | 输入 |
| 发送按钮 | 提交 |
| 切换 Agent | 切换 |
| 清空对话 | 重置 |

### 5.3 点击后会发生什么

| 点击 | 行为 |
|---|---|
| **选择 Agent 卡片** | 进入对话界面，显示该 Agent 的欢迎语 |
| **发送消息** | 消息即时上屏（用户气泡）→ Agent 回复**流式输出**（逐字） |
| **切换 Agent** | 提示"切换后对话上下文将重置"，确认后切换 |
| **清空对话** | 二次确认后清空 |

**流式响应必须处理的三种情况**（依据 `11.清单` 对"流式响应"的定义）：

| 情况 | 处理 |
|---|---|
| 正常输出完 | 关闭连接，显示完成态 |
| 用户中途取消 | 停止生成，保留已输出内容 |
| 网络断开 | 提示**"连接中断"**，**不能把半截内容当完整结果** |

> 原文依据：`11.清单` 第 47 条流式响应话术——"不要把半截内容当完整结果"。

### 5.4 加载 / 空 / 错误

| 状态 | 处理 |
|---|---|
| **等待回复** | 打字机逐字显示 + "思考中"提示 |
| **对话为空** | 显示 Agent 欢迎语 + 3 个推荐提问（示例问题） |
| **输入为空** | 发送按钮禁用 |
| **接口失败** | 保留用户输入 + "AI 暂时没响应" + **重试**按钮 |
| **超时** | 提示"响应超时" + 重试 |
| **日额度用尽**（如有） | 友好提示 + 明日再来 |
| **Agent 不可用** | 卡片置灰 + "即将上线" |

⚠️ **未定义项**（待需求补充）：
- 两个 Agent 的具体能力边界与对话流程
- 是否保留多轮上下文、保留几轮
- 是否有预设提示词模板
- 是否需要登录 / 额度控制
- 是否返回引用来源

## 六、跨页面交互流

### 6.1 典型路径

**路径 A：查词（最高频）**
```
首页 → 搜索框输入 → 搜索筛选页（结果） → 名词详情页 → 复制话术 → 相关推荐 → …
```

**路径 B：系统学习**
```
首页 → 🎨 做好看卡片 → Wiki 长页 → TOC 跳章节 → 复制话术 → 回到首页 → 下一个能力
```

**路径 C：按分类浏览**
```
首页 → 📖 准确聊 → 搜索筛选页（分类卡片） → 该分类词列表 → 名词详情页
```

**路径 D：找 AI 帮忙**
```
首页 → 陪练对话 tab → 选 Agent → 提问 → 流式回复
```

### 6.2 返回行为

| 场景 | 行为 |
|---|---|
| 从详情页返回 | 回到来源页，**保持原滚动位置** |
| 从搜索结果进详情再返回 | 搜索结果**不丢失**（关键词、结果列表保持） |
| 浏览器后退 | 正常回退，不强制跳首页 |

> 依据：`22.设计` 的"状态问题"——用户不该因返回而丢失已做的操作。

### 6.3 全局快捷键（可选）

| 键 | 行为 |
|---|---|
| `/` | 聚焦搜索框 |
| `Esc` | 关闭搜索框 / 取消输入 |
