# 造物笔记 · 文档命名规范

> 本标准从项目现有 8 份设计文档中归纳得出，作为**后续所有文档类文件的命名依据**。
>
> 建立日期：2026-09-26

---

## 一、命名格式

```
编号.领域：内容主题.md
```

**示例**：`22. 架构：页面交互架构.md`

| 组成 | 规则 | 说明 |
|---|---|---|
| **编号** | 两位数字 | `00` / `01` / `11` / `22` / `90` |
| **分隔符** | 英文句点 `.` | 紧跟编号，无空格 |
| **领域词** | 2-3 字中文 | 概括文档性质，如 顶层 / 命名 / 创意 / 架构 / 调试 |
| **分隔符** | 全角冒号 `：` | 中文标点 |
| **内容主题** | 中文描述 | 说清这份文档讲什么 |
| **扩展名** | `.md` | 统一 Markdown |

---

## 二、编号段位规则

现有文档的编号呈现明显分段，建议沿用：

| 段位 | 用途 | 现有实例 |
|---|---|---|
| **00** | 顶层总纲 | 00.顶层：顶层文档 |
| **01-09** | 立意层（为什么做、叫什么、有什么创意） | 01. 命名 / 02. 创意 |
| **10-19** | 内容层（知识资产本身） | 11. 清单 / 12.D版 |
| **20-29** | 设计层（页面、交互、视觉、实现策略） | 22. 架构 / 22.设计 / 23. 调试 |
| **90+** | 管理类（需求、规范、评审、计划等） | 90. 需求 |

## 三、领域词词表

新增文档时，**优先复用**以下已用领域词；确需新造时保持 2-3 字中文。

| 领域词 | 适用内容 |
|---|---|
| 顶层 | 项目总纲、定位、价值 |
| 命名 | 品牌命名与探索过程 |
| 创意 | 创意点、惊喜设计 |
| 清单 | 条目式汇总（如名词清单） |
| 架构 | 页面结构、交互架构 |
| 设计 | 视觉与体验设计 |
| 调试 | 调试方法论 |
| 需求 | 需求梳理与清单 |
| 规范 | 标准、约定 |
| 评审 | 审查记录 |
| 计划 | 排期与推进 |

## 四、特殊后缀约定

| 后缀 | 含义 | 实例 |
|---|---|---|
| ` √` | 版本已定稿 / 已确认 | `12.D版：4层金字塔分类 √.md` |

> 定稿标记放在内容主题之后、扩展名之前，前面留一个空格。

---

## 五、注意事项

1. **编号与主题之间用全角冒号 `：`**，不用半角 `:`——现有文档中仅半角冒号出现于小标题，文件名统一用全角。
2. **领域词后紧跟冒号**，中间不加空格（`22. 架构：` 的编号后空格属历史遗留，新文档建议统一为 `22.架构：`）。
3. **文件名不含版本号**——版本由 Git 标签管理，不写进文件名。
4. **同一文档多版本**可用后缀区分（如 `D版`），但需保持编号一致。
5. **不出现英文空格分词**，保持中文连续可读。
