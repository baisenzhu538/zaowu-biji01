# VibeHandBook · Top 50 名词清单（D版 · 4 层金字塔）

> 分类方案：**4 大类 + 内部分组**，按"先懂、再写、再搭、再交"的自然递进组织。
>
> 一句话记住结构：**看懂网页 → 学会写代码 → 搭出系统 → 交付上线**。

---

## 总：为什么是 4 层？

现有 9 个分类的问题：分类太多、大小不均（有的分类只有 2 个词）、边界模糊、缺乏递进主线。

D 版只分 **4 个大类**，每个大类内部自然分成 2-3 个子组。大类之间有一条清晰的递进主线：

> **第一章：先从"看到"开始**——你打开一个网页，这背后是什么在运转？
> **第二章：才能"写起来"**——你要写代码了，用什么语言、什么工具？
> **第三章：然后"搭系统"**——代码多了，怎么组织数据、设计架构？
> **第四章：最终"交出去"**——怎么找 Bug、怎么测试、怎么上线？

每章的子组不做强制编号，只是帮你在章内快速定位——就像一本书的章节里分了几个小节。

## 分：50 个名词详解

---

## 第一章 · Web 是什么（15 词）

> 打开浏览器，输入网址，看到页面——这背后是一整套东西在协作。这一章帮你搞懂整条链路。

### 地址和传输

你看到的每一个网页，背后都有一个地址和一套传话规则。

#### 01. 域名 / Domain

- **一句话解读**：域名是人容易记住的网站名称，指向提供服务的服务器地址。
- **大白话解读**：域名像网站的店名或门牌名称，不等于网站内容本身。
- **专业理解**：域名通过 DNS 解析到 IP 地址，可配置不同记录指向网站、邮件或其他服务。
- **Vibe 常用话术**：
  - `我买了一个域名，帮我把网站绑到这个域名上。`
  - `线上域名能打开，但测试域名打开是空白页，你查一下是不是域名指向的环境不对。`
  - `我把域名从 A 服务器换到 B 服务器了，但有些用户还是看到旧页面，你帮我查一下是不是 DNS 缓存没生效，大概要等多久。`

#### 02. DNS / Domain Name System

- **一句话解读**：DNS 把域名翻译成 IP 地址，让浏览器找到正确的服务器。
- **大白话解读**：你记住的是店名，DNS 帮你查到这家店实际在哪条街。
- **专业理解**：DNS 保存并返回域名与 IP、邮件服务等资源记录；修改后可能有缓存和传播时间。
- **Vibe 常用话术**：
  - `帮我看看这个域名现在解析到哪个 IP 了。`
  - `域名打不开了，你帮我查一下是不是 DNS 解析出了问题。`
  - `我改了 DNS 记录指向新服务器，但过了半天还是访问的旧 IP，你帮我看看 TTL 设的是多少，有没有办法加速生效。`

#### 03. URL / Uniform Resource Locator

- **一句话解读**：URL 是网页、文件或接口资源的完整地址。
- **大白话解读**：URL 就是网页的门牌号，包含去哪儿以及要找哪个房间。
- **专业理解**：URL 通常由协议、域名、路径、查询参数和片段组成，浏览器据此定位资源。
- **Vibe 常用话术**：
  - `你帮我每一个商品页都加上独立的 URL。`
  - `这个列表页的 URL 不对，你检查一下问题出在哪了。`
  - `URL 里的参数不对，你帮我检查一下配置的参数是不是正确的，特别是分页参数和筛选参数的顺序。`

#### 04. HTTP / Hypertext Transfer Protocol

- **一句话解读**：HTTP 规定浏览器如何请求内容、服务器如何返回结果。
- **大白话解读**：HTTP 是浏览器和服务器之间约定好的传话格式。
- **专业理解**：HTTP 定义请求方法、请求头、请求体、响应、状态码等通信规则；它本身不负责业务判断。
- **Vibe 常用话术**：
  - `帮我用 GET 方法请求这个接口，看看返回什么。`
  - `这个接口报错了，你帮我看一下是 GET 还是 POST 请求，请求体里带了什么参数。`
  - `这个接口有时候通有时候报错，你帮我抓一下 HTTP 请求，看看请求头、请求体和响应分别是什么，是不是参数格式有问题。`

#### 05. HTTPS / Hypertext Transfer Protocol Secure

- **一句话解读**：HTTPS 是带加密传输和证书校验的 HTTP。
- **大白话解读**：它像给浏览器和网站之间的对话加了防偷听的信封。
- **专业理解**：HTTPS 通过 TLS 保护传输内容并校验服务端身份，但不代表网站内容本身一定可信。
- **Vibe 常用话术**：
  - `帮我把网站从 HTTP 换成 HTTPS。`
  - `网页上提示"不安全"，你帮我看看是不是 HTTPS 证书过期了。`
  - `HTTPS 证书配好了但页面里有些图片还是 HTTP 加载的，浏览器报混合内容警告，你帮我把这些资源全部改成 HTTPS。`

### 页面三件套

任何网页都是由这三样东西组成的——骨架、肌肉、衣服。

#### 06. HTML / HyperText Markup Language

- **一句话解读**：HTML 定义网页的内容、结构和语义骨架。
- **大白话解读**：HTML 像人的骨架，决定标题、段落、图片和按钮放在哪里。
- **专业理解**：HTML 使用标签构造文档结构，由浏览器解析为 DOM；它不主要负责视觉样式。
- **Vibe 常用话术**：
  - `帮我把这个页面结构搭出来，标题、内容区、底部导航。`
  - `这个页面的结构有点乱，标题层级不对，你帮我重新整理一下 HTML 的语义结构。`
  - `这个页面在手机上显示错位了，你帮我检查一下 HTML 结构，看看是不是有标签没闭合或者嵌套层级有问题。`

#### 07. CSS / Cascading Style Sheets

- **一句话解读**：CSS 控制网页的颜色、字体、布局、间距、响应式和视觉状态。
- **大白话解读**：CSS 像衣服和化妆，决定页面看起来什么样。
- **专业理解**：CSS 通过选择器、层叠规则和布局模型影响元素的呈现，不负责业务数据处理。
- **Vibe 常用话术**：
  - `帮我把这个按钮的背景色改成蓝色，圆角加大一点。`
  - `这个布局在电脑上没问题，但手机上就错位了，你帮我看看 CSS 的响应式是不是有问题。`
  - `页面里好多组件的颜色和间距都不统一，你帮我先定一套设计规范，把主色、字号、间距这些变量定好，然后统一应用，别一个个改。`

#### 08. JavaScript / JavaScript

- **一句话解读**：JavaScript 让网页能响应点击、输入、数据请求和动态变化。
- **大白话解读**：HTML 是骨架，JavaScript 像肌肉和神经，让页面动起来。
- **专业理解**：JavaScript 可运行在浏览器或服务器环境中，处理交互、状态、异步请求和业务逻辑。
- **Vibe 常用话术**：
  - `帮我给这个按钮加一个点击事件，点了之后弹个提示。`
  - `按钮点了没反应，你帮我看看 JavaScript 里事件绑定有没有问题。`
  - `页面上有个表单，提交之后有时候成功有时候没反应，你帮我查一下是不是没有处理 loading 状态导致用户重复点击。`

### 系统全景

页面背后是一套系统在运转——前端后端怎么分工、服务器跑在哪里、怎么访问。

#### 09. 前端与后端 / Frontend & Backend

- **一句话解读**：前端负责用户看到和操作的部分，后端负责服务器上的数据、规则和业务处理。
- **大白话解读**：前端像餐厅前厅，后端像看不见的厨房；你点菜之后，厨房处理好再把结果端出来。
- **专业理解**：前端运行在浏览器等客户端，后端运行在服务器端，二者通过请求和响应协作。
- **Vibe 常用话术**：
  - `帮我把首页这个页面做出来，数据从后端拿。`
  - `前端页面已经做好了，但后端接口还没接上，你先帮我用假数据跑通。`
  - `这个功能前端显示没问题，但后端返回的数据格式不对，你帮我看看是前端解析的问题还是后端返回的问题。`

#### 10. 服务器 / Server

- **一句话解读**：服务器是持续运行并通过网络提供网页、数据或计算服务的计算机或云资源。
- **大白话解读**：服务器像一台长期值班、专门响应别人请求的电脑。
- **专业理解**：服务器承担请求处理、数据存储、任务执行等职责，强调稳定性、安全性和并发能力。
- **Vibe 常用话术**：
  - `帮我把这个项目部署到服务器上。`
  - `网站突然打不开了，你帮我看看是不是服务器挂了。`
  - `服务器一到晚上高峰期就卡，你帮我查一下是 CPU 满了还是内存不够，需不需要升级配置或者加负载均衡。`

#### 11. 端口 / Port

- **一句话解读**：端口用数字区分同一台服务器上的不同网络服务。
- **大白话解读**：IP 像一栋楼的地址，端口像楼里的不同房间。
- **专业理解**：端口范围为 0–65535，服务通过 IP 加端口监听特定连接。
- **Vibe 常用话术**：
  - `帮我启动项目，默认端口 3000 就行。`
  - `项目启动报错了，说端口被占用，你帮我看看是哪个程序占了这个端口。`
  - `前端跑在 3000 端口，后端跑在 8080 端口，前端请求后端时报跨域，你帮我在开发环境配一下代理，把 8080 的请求转发过去。`

#### 12. Localhost / localhost

- **一句话解读**：localhost 指当前这台设备自己，通常用于本地开发访问。
- **大白话解读**：你在电脑上打开 localhost，访问的是这台电脑，不是互联网网站。
- **专业理解**：localhost 通常解析到本机回环地址 127.0.0.1；其他设备不能直接用它访问你的电脑服务。
- **Vibe 常用话术**：
  - `帮我在 localhost 上跑起来看看效果。`
  - `我在电脑上用 localhost 能打开，但手机上访问不了，怎么办？`
  - `localhost 跑的没问题，但换成局域网 IP 就报跨域错误了，你帮我看看是不是开发服务器的 host 配置要改一下。`

#### 13. 后台 / 管理后台 / Admin Panel

- **一句话解读**：后台是给管理员或运营人员管理数据、用户、配置和内容的界面。
- **大白话解读**：普通用户看到的是前台，商家改价格、看订单、管内容用的是后台。
- **专业理解**：后台通常需要登录和权限控制，面向内部操作，不应默认暴露给普通用户。
- **Vibe 常用话术**：
  - `帮我做一个管理后台，可以增删改查商品。`
  - `后台登录之后看不到商品列表，你帮我查一下是不是权限没配对。`
  - `管理员和普通运营的权限不一样，管理员能删数据，运营只能看和改，你帮我把权限分开，每个角色能做什么都列清楚。`

#### 14. HTTP 状态码 / HTTP Status Codes

- **一句话解读**：状态码用三位数字说明服务器处理请求的结果。
- **大白话解读**：200 是"好了"，404 是"找不到"，500 是"服务器出问题了"。
- **专业理解**：1xx 为信息，2xx 为成功，3xx 为重定向，4xx 多为客户端问题，5xx 多为服务端问题。
- **Vibe 常用话术**：
  - `接口返回了 404，你帮我看看是不是路径写错了。`
  - `登录接口返回 500，但之前还好好的，你帮我查一下是不是后端出了什么问题。`
  - `这个接口有时候返回 200 但数据是空的，有时候返回 500，你帮我看看什么情况会 500、什么情况数据是空的，然后在代码里把不同状态码对应到不同的用户提示。`

#### 15. API / Application Programming Interface

- **一句话解读**：API 是软件之间按约定交换数据或调用能力的接口。
- **大白话解读**：API 像程序之间的传话员，规定"怎么问、问什么、会得到什么"。
- **专业理解**：Web API 通常通过 HTTP 提供资源和操作，包含路径、方法、参数、认证和响应契约。
- **Vibe 常用话术**：
  - `帮我写一个接口，返回所有商品的列表。`
  - `这个接口前端调了没数据，你帮我看看是 API 地址不对还是参数传错了。`
  - `帮我设计一套 API，商品增删改查各一个接口，列表接口要支持分页和搜索，删除做成软删除不要真删，每个接口的请求参数和返回格式先定义清楚再写代码。`

## 第二章 · 怎么写代码（14 词）

> 看懂网页之后，你要开始写代码了。用什么语言写、数据怎么存、工具怎么配——这一章全部覆盖。

### 语言和数据

写代码的语言选择，以及不同语言之间怎么传数据。

#### 16. Python / Python

- **一句话解读**：Python 是语法清晰、生态丰富的通用编程语言，常用于自动化、数据、AI 和后端。
- **大白话解读**：Python 比较像人话，适合把重复工作写成脚本交给电脑执行。
- **专业理解**：Python 由解释器运行，拥有丰富的标准库和第三方生态，适合快速开发多类程序。
- **Vibe 常用话术**：
  - `帮我用 Python 写个脚本，把这个 Excel 里的数据读出来。`
  - `Python 脚本能跑了，但有些数据读出来是空的，你帮我看看是不是文件编码或者格式的问题。`
  - `帮我用 Python 写一个后端接口，接收前端的 POST 请求，把数据存到数据库里，注意处理异常情况和返回正确的状态码。`

#### 17. TypeScript / TypeScript

- **一句话解读**：TypeScript 在 JavaScript 基础上增加类型检查，帮助提前发现传值错误。
- **大白话解读**：它像写代码时旁边有个老师，发现"这里应该是数字却传了文字"。
- **专业理解**：TypeScript 编译成 JavaScript 执行，类型系统提升可维护性，但不能替代运行时校验。
- **Vibe 常用话术**：
  - `帮我把这个函数的参数和返回值都加上类型。`
  - `TypeScript 报了一堆类型错误，你帮我看看是哪里传参类型不对。`
  - `这个接口返回的数据结构比较复杂，你帮我把 TypeScript 的类型定义写全，特别是嵌套对象和数组部分，然后检查一下前端调用的地方有没有类型不匹配。`

#### 18. Markdown / Markdown

- **一句话解读**：Markdown 用少量符号编写结构化纯文本，可转换为网页或文档。
- **大白话解读**：用 `#` 写标题、用 `-` 写清单，不用复杂排版软件也能写清楚。
- **专业理解**：Markdown 支持标题、列表、代码块、链接、图片和表格等常见文档结构。
- **Vibe 常用话术**：
  - `帮我把这个需求用 Markdown 整理一下，列清楚要做什么。`
  - `你帮我把这个 Markdown 文档转成网页，保留标题、列表和代码块的格式。`
  - `帮我写一个 Markdown 需求模板，以后每次提需求都按这个来：需求背景、功能列表、接口定义、验收标准，方便 AI 直接按结构实施。`

#### 19. JSON / JSONL / JSON & JSON Lines

- **一句话解读**：JSON 是程序间传递结构化数据的格式，JSONL 是一行一个 JSON 对象。
- **大白话解读**：JSON 像程序之间约定好的标准表格；JSONL 像一条一条连续写的记录。
- **专业理解**：JSON 以对象、数组、键值组织数据；JSONL 适合流式处理或逐行处理大量记录。
- **Vibe 常用话术**：
  - `帮我把这组数据整理成 JSON 格式。`
  - `接口返回的 JSON 解析报错了，你帮我看看是不是格式有问题，比如多了个逗号或者引号没闭合。`
  - `这个接口返回的数据有时候是对象有时候是数组，前端处理容易出错，你帮我统一一下 JSON 返回格式，正常返回对象，列表返回数组，错误返回统一的错误结构。`

#### 20. SQL / Structured Query Language

- **一句话解读**：SQL 是查询和修改关系型数据库的语言。
- **大白话解读**：SQL 就是和数据库对话：请它查、加、改或删哪些数据。
- **专业理解**：SQL 支持增删改查、关联、筛选和聚合；MySQL、PostgreSQL、SQLite 等实现存在差异。
- **Vibe 常用话术**：
  - `帮我写个 SQL，查出所有价格大于 100 的商品。`
  - `这个 SQL 查出来的数据不对，少了好几条，你帮我看看是不是条件写错了或者关联表关联漏了。`
  - `帮我写一个 SQL，关联商品表、订单表和用户表，查出最近 30 天每个用户买了什么、总金额多少，按金额从高到低排，注意没有订单的用户也要显示出来。`

### 工具和环境

光会写不行，还得能让代码"跑起来"——环境怎么配、工具怎么用。

#### 21. 运行环境 / Runtime

- **一句话解读**：运行环境是程序执行所需的操作系统、解释器、依赖和配置集合。
- **大白话解读**：程序像鱼，运行环境就是它需要的水；没有环境，代码只是文字。
- **专业理解**：不同语言和框架依赖特定运行时，如浏览器、Node.js 或 Python 解释器。
- **Vibe 常用话术**：
  - `帮我看看这个项目需要什么环境才能跑起来。`
  - `我电脑上跑不了，报了一堆找不到模块的错误，你帮我看看是不是环境没配好。`
  - `项目在我电脑上能跑，但到了服务器上就报版本不对，你帮我把需要的 Node 版本、Python 版本、依赖包版本都列出来，写个环境配置说明。`

#### 22. IDE / Integrated Development Environment

- **一句话解读**：IDE 把代码编辑、补全、运行、调试和项目管理集中在一起。
- **大白话解读**：IDE 是程序员的超级记事本，能检查、运行和追踪代码。
- **专业理解**：IDE 通常集成编辑器、调试器、编译工具、终端和版本管理等能力。
- **Vibe 常用话术**：
  - `帮我在 IDE 里配置一下这个项目的启动方式。`
  - `IDE 里代码不报错了但运行不了，你帮我看看是不是运行配置或者调试配置没设对。`
  - `IDE 里 TypeScript 文件不提示了，格式化也不生效，你帮我检查一下是不是插件配置有问题，或者 tsconfig.json 的配置影响了 IDE 解析。`

#### 23. CLI / Command Line Interface

- **一句话解读**：CLI 通过文字命令与计算机交互。
- **大白话解读**：CLI 就是终端里敲命令，不靠鼠标点按钮。
- **专业理解**：CLI 适合启动服务、管理文件、安装依赖、执行脚本和版本控制，命令也便于自动化。
- **Vibe 常用话术**：
  - `帮我在终端跑一下这个命令，看看输出什么。`
  - `命令行报错了，你帮我看看是不是命令写错了，还是要在哪个目录下执行。`
  - `你帮我把这个操作写成一个 CLI 脚本，以后每次部署只要在终端敲一行命令就行，不要每次都手动一步步操作。`

#### 24. npm / Node Package Manager

- **一句话解读**：npm 用来安装 JavaScript 项目的依赖并执行预设脚本。
- **大白话解读**：npm 像项目材料管理员，负责把需要的代码包装好并启动常用命令。
- **专业理解**：npm 管理 package.json、lock 文件、依赖版本和 scripts；它不替项目自动完成业务功能。
- **Vibe 常用话术**：
  - `帮我安装一下这个项目需要的依赖。`
  - `npm install 报错了，你帮我看看是不是版本冲突或者网络问题。`
  - `项目之前能跑，今天 npm install 之后突然报错，你帮我看看 package.json 里有没有依赖版本变了，lock 文件有没有更新，是不是需要锁版本。`

#### 25. 环境变量 / Environment Variables

- **一句话解读**：环境变量把密码、API 密钥、服务地址等配置放在代码之外。
- **大白话解读**：它像程序启动前要看的便条，换环境时换便条，不用重写代码。
- **专业理解**：环境变量支持开发、测试、生产环境切换，但敏感值仍需权限控制、脱敏和安全存储。
- **Vibe 常用话术**：
  - `帮我把数据库密码和 API 密钥放到环境变量里，不要写死在代码里。`
  - `代码里用了环境变量但本地跑不通，你帮我看看是不是 .env 文件没配或者变量名写错了。`
  - `开发环境和生产环境的环境变量不一样，你帮我理一下哪些变量必须配、每个环境填什么值，再写个 .env.example 模板，千万别把真实密钥提交到代码仓库。`

#### 26. Docker / Docker

- **一句话解读**：Docker 把应用、依赖、配置和运行环境打包成可搬运的容器。
- **大白话解读**：把程序连同它需要的一切装进箱子，搬到另一台电脑也尽量保持一致。
- **专业理解**：Docker 通过镜像和容器隔离运行环境，减少"在我电脑上能跑"的差异。
- **Vibe 常用话术**：
  - `帮我用 Docker 把这个项目打包一下。`
  - `Docker 容器启动了但访问不了，你帮我看看是不是端口映射或者网络配置有问题。`
  - `帮我写一个 Dockerfile 和 docker-compose 配置，前端、后端、数据库三个服务都打包进去，注意端口别冲突，数据库数据要持久化，环境变量也要配好。`

#### 27. 编译 / Compile

- **一句话解读**：编译把源代码转换为运行时可以执行的代码或中间产物。
- **大白话解读**：把人写的代码翻译成电脑能执行的机器话。
- **专业理解**：编译可能包含类型检查、语法转换、打包和优化；TypeScript 等通常编译为 JavaScript。
- **Vibe 常用话术**：
  - `帮我把这个 TypeScript 文件编译成 JavaScript。`
  - `编译报了一堆错误，你帮我看看是语法问题还是类型问题。`
  - `本地编译没问题，但部署到服务器上编译就失败了，你帮我看看是不是服务器上编译工具版本不对，或者有些编译依赖没装上。`

#### 28. 版本管理 / Git / Version Control

- **一句话解读**：Git 记录文件变更历史，支持回滚、分支和协作。
- **大白话解读**：Git 是代码的时光机，关键节点可以拍快照，写坏了能回到过去。
- **专业理解**：Git 是分布式版本控制系统，核心对象包括提交、分支、远程仓库和合并。
- **Vibe 常用话术**：
  - `帮我把这段代码提交一下，写个提交说明。`
  - `我改了一堆东西不知道改了啥，你帮我 git diff 看一下，然后整理一下提交信息。`
  - `我在这个分支上改了很多，现在要合并回主分支，你帮我先看看有没有冲突，冲突了怎么解决，合并之前先确认能回滚。`

#### 29. Git 常用操作 / Commit · Push · Pull · Merge · Add

- **一句话解读**：add 选择改动，commit 保存快照，push 上传，pull 拉取，merge 合并。
- **大白话解读**：选照片、拍照片、上传云端、下载更新、把两条修改路线拼起来。
- **专业理解**：这些命令分别作用于暂存区、本地仓库、远程仓库和分支整合流程。
- **Vibe 常用话术**：
  - `帮我 git add 再 commit，然后 push 到远程仓库。`
  - `我 pull 的时候有冲突，你帮我看看怎么解决，不要覆盖我本地的改动。`
  - `我在错误的分支上提交了代码，你帮我把这个提交挪到正确的分支去，用 cherry-pick 还是 reset 重新提交，操作之前先确认当前状态是干净的。`

## 第三章 · 怎么搭系统（8 词）

> 代码能跑了，但要做成一个真正可用的系统——数据怎么存、状态怎么管、架构怎么设计。

### 数据和状态

网站不是静态的——用户登录、购物车、偏好设置都需要"记住"。

#### 30. 数据库 / Database

- **一句话解读**：数据库按结构长期存储、查询和更新应用数据。
- **大白话解读**：数据库像一个能多人同时使用、还能快速查找的大号 Excel。
- **专业理解**：关系型数据库以表、行、列组织数据，并提供查询、约束、事务和索引等能力。
- **Vibe 常用话术**：
  - `帮我建一个商品表，包含名称、价格、库存这些字段。`
  - `数据库查询很慢，你帮我看看是不是需要加索引。`
  - `帮我设计整个项目的数据库表结构，用户、商品、订单三张表，订单要关联用户和商品，注意一个订单包含多个商品的情况，字段、类型、关联关系都列出来再建表。`

#### 31. Cookie / Cookie

- **一句话解读**：Cookie 是浏览器保存并在后续请求中携带的小型数据。
- **大白话解读**：网站给浏览器贴一张便签，下次回来就知道你是谁或记得你的偏好。
- **专业理解**：Cookie 可保存会话标识、偏好等，具有域、路径、过期、Secure、HttpOnly 等属性。
- **Vibe 常用话术**：
  - `帮我在用户登录之后存一个 Cookie，记住登录状态。`
  - `用户说每次刷新都要重新登录，你帮我看看 Cookie 是不是没设过期时间。`
  - `登录状态在 HTTP 下能保持，但切到 HTTPS 就丢了，你帮我查一下是不是 Cookie 的 Secure 属性配置的问题，SameSite 属性需不需要设。`

#### 32. Session / Session

- **一句话解读**：Session 是服务器保存的用户会话状态，浏览器通常只携带会话 ID。
- **大白话解读**：卡片上只有编号，真正的个人信息和状态放在图书馆服务器里。
- **专业理解**：用户登录后服务端创建会话，客户端通过 Cookie 等方式携带 Session ID 完成后续识别。
- **Vibe 常用话术**：
  - `帮我实现一个登录功能，登录之后创建 Session。`
  - `用户登录之后过一会儿就掉线了，你帮我看看 Session 过期时间设的是多少。`
  - `用户在手机上登录了，又用电脑登录，之前的 Session 要不要失效？多设备登录怎么处理，你帮我把这个逻辑理清楚。`

#### 33. 缓存 / Cache

- **一句话解读**：缓存把常用数据放在更快的位置，减少重复计算和数据库压力。
- **大白话解读**：常用的盐放在灶台边，不用每次都跑储藏室。
- **专业理解**：缓存需要考虑命中率、过期、失效、更新一致性和容量，不能把它当永久数据源。
- **Vibe 常用话术**：
  - `帮我把首页的数据缓存起来，不用每次都查数据库。`
  - `数据改了但页面还是显示旧的，你帮我看看是不是缓存没更新。`
  - `帮我设计一下缓存策略，哪些数据适合缓存、缓存多久过期、数据更新后怎么让旧缓存失效，还要考虑缓存击穿和雪崩的情况。`

### 设计与架构

代码多了，就需要"设计"——模块怎么拆、任务怎么跑、依赖怎么减少。

#### 34. 同步 / 异步 / Synchronous · Asynchronous

- **一句话解读**：同步要等前一步完成，异步发起任务后可继续处理其他事情。
- **大白话解读**：同步像排队打饭，异步像点外卖，等结果时可以先做别的事。
- **专业理解**：同步调用会阻塞当前流程；异步通过回调、事件、Promise 或消息机制在完成后通知。
- **Vibe 常用话术**：
  - `帮我把这个操作改成异步的，不要让用户等着。`
  - `异步任务执行完了但页面没更新，你帮我看看是不是回调没正确处理。`
  - `这个流程里有三个异步操作，有前后依赖关系，还可能超时和失败，你帮我用 async/await 把整个流程串起来，每个环节都处理成功和失败，失败了要能重试。`

#### 35. 解耦 / Decoupling

- **一句话解读**：解耦降低模块之间的直接依赖，使修改和测试更局部。
- **大白话解读**：显示器坏了换显示器，不必把整台电脑都扔掉。
- **专业理解**：模块通过稳定接口协作，减少内部实现相互渗透，从而提高可维护性和扩展性。
- **Vibe 常用话术**：
  - `帮我把这个功能拆成独立模块，别全写在一个文件里。`
  - `我想换一个支付方式，但支付逻辑和订单逻辑混在一起了，你帮我先拆开再改。`
  - `项目越来越大了，功能之间互相依赖，改一个地方影响一片，你帮我按模块重新拆分，每个模块通过接口对外提供服务，方便后面单独测试和替换。`

#### 36. 多线程 / Multithreading

- **一句话解读**：多线程让一个程序中的多个执行单元并行或交错处理任务。
- **大白话解读**：一个厨房里多个厨师同时做菜，速度可能更快，但抢锅时也会出问题。
- **专业理解**：线程共享进程资源，可提升并发处理能力，也带来竞争、死锁和同步复杂度。
- **Vibe 常用话术**：
  - `帮我把这个批量任务改成多线程跑，加快速度。`
  - `多线程跑起来之后数据偶尔会错乱，你帮我看看是不是共享数据没加锁。`
  - `帮我用多线程处理这个任务，注意共享资源加锁、线程之间不能死锁、出了异常要能捕获不影响其他线程，最后等所有线程跑完再汇总结果。`

### 体验能力

系统搭得再好，用户用起来不顺也白搭。

#### 37. UI / UE / UX / User Interface & User Experience

- **一句话解读**：UI 关注界面呈现，UX 关注用户完成目标的整体体验，UE 常作用户体验的中文缩写使用。
- **大白话解读**：UI 是"看起来和点起来怎样"，UX 是"整个过程顺不顺、能不能把事办成"。
- **专业理解**：UI 涉及视觉和交互界面，UX 涉及任务流程、信息架构、可用性、反馈和情绪感受；二者相互影响。
- **Vibe 常用话术**：
  - `帮我把这个页面的 UI 弄好看一点，配色和间距统一一下。`
  - `用户反馈说这个页面不知道下一步该干嘛，你帮我看看 UX 流程是不是有问题。`
  - `帮我重新设计这个页面的体验：先想清楚用户来这里要完成什么任务，把空状态、加载中、出错、成功这几种情况都设计好，最后再调颜色和样式，不要一上来就纠结配色。`

## 第四章 · 怎么交付和维护（13 词）

> 代码写好了、系统搭好了，然后呢？找 Bug、写测试、部署上线、持续维护——这是从"能跑"到"能用"的最后一步。

### 找 Bug 和测试

软件一定会有 Bug，关键是能快速找到、修好、不再犯。

#### 38. Bug / Bug

- **一句话解读**：Bug 是程序实际行为与预期不一致的缺陷。
- **大白话解读**：按钮没反应、价格错了、密码对却登不上，都是可能的 Bug。
- **专业理解**：Bug 可能来自逻辑、边界条件、类型、环境、依赖或数据等问题。
- **Vibe 常用话术**：
  - `这个页面有个 Bug，按钮点了没反应，你帮我修一下。`
  - `这个 Bug 时有时无，不是每次都能复现，你帮我看看可能是什么原因。`
  - `帮我定位这个 Bug：什么操作步骤下出现、实际结果是什么、预期应该是什么、最近改了什么代码，先稳定复现再修，不要猜着改。`

#### 39. Debug / Debugging

- **一句话解读**：Debug 是定位、分析并修复 Bug 的过程。
- **大白话解读**：像破案：重现现场、查看线索、缩小范围、修复后再验证。
- **专业理解**：调试可使用日志、断点、变量检查、网络面板、最小复现和回归测试。
- **Vibe 常用话术**：
  - `帮我看看这个报错是什么意思，怎么修。`
  - `页面上不显示报错但功能不对，你帮我加几行日志看看数据流转到哪一步出了问题。`
  - `这个 Bug 我找了半天没找到原因，你帮我先复现一遍，然后看日志、打断点、查网络请求，把范围缩小到具体哪行代码或哪个接口，确认原因再改。`

#### 40. 测试（单元 / 集成 / 回归 / 端到端） / Testing

- **一句话解读**：测试用不同粒度验证代码、模块协作和完整用户流程。
- **大白话解读**：单元测螺丝，集成测发动机配合，回归防止旧功能被弄坏，端到端像真人试驾。
- **专业理解**：单元测试最小模块，集成测试模块间协作，回归测试已有能力，E2E 模拟真实使用链路。
- **Vibe 常用话术**：
  - `帮我写个简单的测试，看看这个函数输出对不对。`
  - `我改了一处代码，结果之前的功能不好使了，你帮我跑一下测试看看哪个用例挂了。`
  - `帮我把这个功能的核心路径都写上测试用例，正常流程、边界值、空数据、权限不足、重复提交这些都要覆盖，改完先跑测试再上线。`

#### 41. Mock / Mock Data

- **一句话解读**：Mock 用模拟对象、接口或数据代替尚未准备好的真实依赖。
- **大白话解读**：先用道具演一遍流程，等真正的演员或后台准备好再换上。
- **专业理解**：Mock 可隔离外部服务、控制返回结果并稳定测试，但不能证明真实依赖一定可用。
- **Vibe 常用话术**：
  - `后端接口还没好，你先帮我用 Mock 数据把页面跑通。`
  - `Mock 数据能显示，但换成真实接口就不行，你帮我看看是数据格式不一样还是请求方式不对。`
  - `帮我把所有 Mock 数据统一管理，标清楚哪些是假的，等后端接口一个个上线之后逐个替换，每替换一个就测一遍，不要到最后一起换搞不清哪个出了问题。`

#### 42. 测试用例 / Test Case

- **一句话解读**：测试用例把输入、操作步骤、预期结果和实际结果写成可重复检查的记录。
- **大白话解读**：不是"我试过了"，而是写清楚谁、在什么条件下、怎么操作、应该看到什么。
- **专业理解**：测试用例通常包含前置条件、数据、步骤、预期、优先级和结果状态。
- **Vibe 常用话术**：
  - `帮我列一下这个登录功能的测试用例。`
  - `测试用例跑过了但线上还是出问题，你帮我看看是不是有些边界场景没覆盖到。`
  - `帮我为这个表单提交功能写完整的测试用例：正常输入、空值、超长文本、特殊字符、重复提交、网络超时，每种情况的预期结果都写清楚。`

### 部署和运维

测试通过了，是时候把东西"发出去"给人用了。

#### 43. 部署 / Deployment

- **一句话解读**：部署把可运行版本发布到目标环境，让用户通过网址或客户端使用。
- **大白话解读**：把在本地做好的东西搬到一台对外营业的机器上。
- **专业理解**：部署包含构建、配置、发布、迁移、健康检查、回滚和上线后验证。
- **Vibe 常用话术**：
  - `帮我把这个项目部署到线上去。`
  - `部署之后页面能打开但接口报错，你帮我看看是不是环境变量没配或者数据库连不上。`
  - `帮我把整个部署流程理清楚：先构建、再配环境变量、然后部署、部署完做健康检查、出问题怎么回滚、上线后验证哪些功能，写个流程文档以后照着做。`

#### 44. Vercel / Vercel

- **一句话解读**：Vercel 是常用于部署前端和 Web 应用的云平台。
- **大白话解读**：把代码连到平台，平台帮你构建并提供一个可访问的网址。
- **专业理解**：Vercel 可连接代码仓库、执行构建、管理预览与生产环境，并提供域名和部分云函数能力。
- **Vibe 常用话术**：
  - `帮我把这个项目部署到 Vercel 上。`
  - `Vercel 上 Preview 环境没问题，但 Production 环境报错了，你帮我看看构建命令或者环境变量是不是不一样。`
  - `Vercel 部署失败了，你帮我看看构建日志报了什么错，是不是依赖没装上或者构建命令不对，另外确认一下输出目录和域名解析。`

#### 45. 日志 / Log / Server Log

- **一句话解读**：日志记录请求、状态、错误和关键运行线索，帮助定位问题。
- **大白话解读**：像监控录像和工作记录，出问题时可以按时间回看。
- **专业理解**：日志应包含足够上下文和关联标识，同时避免密码、Token 等敏感信息泄露。
- **Vibe 常用话术**：
  - `帮我在这个接口里加几行日志，看看请求进来了没有。`
  - `出了 Bug 但不知道哪一步出的问题，你帮我看看日志里有没有报错信息。`
  - `用户反馈页面白屏但说不清什么操作触发的，你帮我查一下日志，按时间范围过滤看看那个时段有没有异常，注意不要把密码和 Token 打在日志里。`

#### 46. Cron Jobs / Scheduled Tasks

- **一句话解读**：Cron Jobs 按时间或周期自动执行任务。
- **大白话解读**：像闹钟，到点自动提醒程序做一件事。
- **专业理解**：定时任务需要配置时间表达式、执行环境、超时、重试、幂等和执行记录。
- **Vibe 常用话术**：
  - `帮我设一个定时任务，每天凌晨自动备份数据库。`
  - `定时任务好像没执行，你帮我看看是不是时间表达式写错了还是服务器上没配好。`
  - `帮我配一个定时任务，每小时跑一次数据同步，注意上一次没跑完下一次不要重复执行，失败了自动重试一次，重试还失败要发通知，还要注意时区问题。`

### 再往前走一步

项目上线了，但技术一直在往前走。这些是 Vibe Coder 下一步会碰到的东西。

#### 47. MCP / Model Context Protocol

- **一句话解读**：MCP 是让模型以统一方式发现和调用外部工具、资源与提示的协议。
- **大白话解读**：像给 AI 接上统一规格的插座，让它知道有哪些工具、怎么用。
- **专业理解**：MCP 规定客户端与服务器之间的能力发现、资源读取、工具调用和消息交互方式；权限仍需单独控制。
- **Vibe 常用话术**：
  - `帮我看看这个 MCP 服务提供了哪些工具可以用。`
  - `MCP 工具调用报错了，你帮我看看是不是参数格式不对或者权限没开。`
  - `我想让 AI 能读我的数据库，帮我把这个能力做成 MCP 工具暴露出去，注意列清楚接收什么参数、是只读还是可写、调用失败返回什么，不要让 AI 有删数据的权限。`

#### 48. 流式响应 / Streaming

- **一句话解读**：流式响应让结果生成一部分就逐步传给用户，而不是全部完成后一次返回。
- **大白话解读**：像边写边展示，不必等整篇文章写完才看到第一行。
- **专业理解**：流式传输降低首字节或首个 Token 的等待感，但不一定减少总耗时，仍需处理断开、结束和错误。
- **Vibe 常用话术**：
  - `帮我把这个 AI 回复改成流式的，一个字一个字往外蹦。`
  - `流式输出到一半就断了，你帮我看看是超时了还是后端断开了连接。`
  - `帮我实现流式响应，注意处理三种情况：正常输出完要关闭连接、用户中途取消要停止生成、网络断开要提示"连接中断"而不是显示成功，不要把半截内容当完整结果。`

#### 49. 沙箱 / Sandbox

- **一句话解读**：沙箱是在受限环境中运行代码或工具，隔离文件、网络和系统权限。
- **大白话解读**：给程序一个围起来的活动场地，能做的事情有限，出问题不容易影响外面。
- **专业理解**：沙箱通过权限、资源和网络隔离降低执行不可信代码的风险，但隔离边界必须经过验证。
- **Vibe 常用话术**：
  - `帮我在沙箱里跑一下这段代码，看看有没有问题。`
  - `沙箱里的代码跑不了，提示没权限，你帮我看看是不是文件读写或者网络访问被限制了。`
  - `帮我配置一下沙箱权限，只允许读取指定目录、不允许写入、不允许访问外网，沙箱里出错误要把错误信息正常返回给用户而不是直接崩掉。`

#### 50. RAG / Retrieval-Augmented Generation

- **一句话解读**：RAG 先检索相关资料，再把资料作为上下文交给模型生成回答。
- **大白话解读**：先去资料库找证据，再让 AI 根据找到的内容回答，而不是只凭记忆。
- **专业理解**：RAG 通常包含切分、索引、召回、排序、上下文拼装和引用；检索质量会直接影响回答质量。
- **Vibe 常用话术**：
  - `帮我把这些文档做成知识库，让 AI 能根据文档回答问题。`
  - `AI 回答的内容和文档里写的不一样，你帮我看看是不是检索没找到对的文档。`
  - `帮我搭一个 RAG 系统，先把文档切片和索引建好，用户提问时先检索最相关的几段，然后让 AI 根据检索内容回答，回答要标注引用来源，检索不到就直接说"没找到相关资料"而不是让 AI 瞎编。`

## 总：D 版的使用指南

### 为什么这个结构对新人友好

4 层的递进逻辑是**自然学习路径**：

1. **第一章（看懂网页）**——你打开一个网站，看到地址栏、页面、交互，先搞懂这些是什么。
2. **第二章（学会写代码）**——你开始动手了，选语言、配环境、用工具。
3. **第三章（学会搭系统）**——代码多了，要考虑数据怎么存、模块怎么拆、体验怎么设计。
4. **第四章（学会交付和维护）**——东西做完了，怎么找 Bug、怎么测试、怎么上线、怎么维护。

新人不需要第一章都没读完就跳去第四章看 RAG。按顺序来，每一步建立在上一步的基础上。
